# Remediation of the audit findings — 2026-10-19

Scope: every finding of the [audit of 2026-10-19](2026-10-19-audit.md) that was still open after the audit, in the priority order given by the organisers, plus the Supabase advisor notices that appeared while applying the fixes. Branch `claude/laughing-hypatia-tirtcp`; development project `LurdyAPP` (eu-west-1, fictional data only); no real participant data exists anywhere.

Method, per issue: root cause from the audit's evidence and the code; fix; a test that would have caught it (SQL suite, Vitest, Playwright); the full regression run (every suite); documentation. Everything marked "tested" ran in a browser or against a database; nothing ran on an iOS or Android device.

**Health score: 88 / 100** (audit: 78). **Verdict: PASS for testing with fictional data. Real participant data: READY ONCE THE ORGANISERS' ITEMS IN §4 ARE DONE. Real health data: NOT READY** (the medical module is a separate, security-gated milestone — schema `medical` stays empty and unreachable).

## 5. Readiness

**Testing with fictional data: ready.** Every automated suite passes, the development project matches the migrations, the e2e scenario covers the whole operational loop including the new sign-in, the pending-badge activation and the offline-safe scanner. A dry run with ~15 team members on their own phones (web build, or an EAS build once the Expo account exists) is the next sensible step and is what the pilot in J §Pilot describes.

**Real participant deployment: not yet, for reasons outside the code.** Needed first, in order: (1) the organisers' decisions R1 and R6 (retention approval, controller, project split, Pro plan with backups verified by a restore); (2) one round on real devices (§3) — in particular the keychain-backed session storage and the camera scanning of invitations, which exist in the code but were never executed on a phone; (3) a staging project with fictional data at pilot volume. With those done, the platform as it stands is suitable for real participant data (names, journeys, rooms, care). **Health data remains out of scope until R3.**

## 6. Health score: 88 / 100

Rationale against the audit's 78: the largest authentication risk (Q5) is closed; the session is encrypted at rest; retention has a mechanism and a clear approval gate; the per-row policy evaluation that would not have scaled is gone; badge reprints no longer have a gap; medical text no longer reaches ordinary incident readers; the three incomplete screens are complete; CI is green on the branch; advisors show no errors. The twelve points withheld: nothing has run on a real device (sessions, camera, GPS, screen reader); no data-restore drill; no hosted load test; the medical module does not exist (by design, but the "health data never reachable" guarantee still rests on there being none).
